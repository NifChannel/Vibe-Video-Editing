# 找素材

将长视频转换为可直接剪辑的独立选段。优先本地计算和本地视觉推理，减少云端图片与长日志。只加载当前项目的必要记录。接口与识别细节见 [本地检索](references/local-vision.md)。

## 开始时的提醒与范围

每次调用都提醒用户“这次是否需要直接跳过每集开头和结尾各1分半？有些片源首尾仍有正片，可以先核对 OP、ED 和预告再排除。”用可用的询问工具征求偏好，同时继续清点文件、检查模型接口和抽查首尾。用户本次已明确指定则直接执行。

未获授权时继续按完整时长检索，可排除已通过画面证据验证的 OP、ED、预告区间。等待不是同意。固定跳过只影响检索范围，保留原文件。以节目版本、片源指纹和集数范围保存排除规则，换源后重新核对，不把一部片的秒数套给另一部。

本次要寻找的角色、动作、是否接受类似演出，以用户正例与纠正为准。先拿少量已知正例和容易混淆的负例试跑，再扩大批次。没有命中允许输出空结果，不为每集凑片段。

## 检索流程

1. 用 FFprobe 清点源路径、大小、修改时间、时长、时间基、真实帧率、画幅和音轨。处理 VFR、不同集帧率和片内分辨率变化，抽帧保存 PTS，不假定全部25fps。
2. 本地 FFmpeg 抽取低分辨率帧，分析有效画幅，移除用于判别的文件黑边。先用背景暗度、颜色比例、镜头变化和已知正例相似度缩小范围。这些是像素运算，不消耗云端视觉 token。
3. 从每秒一帧作为已验证的起点，按目标时长和漏检情况调整。3–5秒一帧可用于长达10–12秒且特征持续的动作，但不能据此保证不漏。局部特征短暂时加密采样。深黑边、粉色等条件只能作为召回线索，必须补查其他光效颜色、背景和演出变体。
4. 合并相邻命中为候选区间，保留前后上下文。候选以单张适当清晰度的原片帧调用本地 Qwen。只问图像事实，程序保存采样时间并组合判定，不让模型猜时间码。多图拼贴只用于最终人工核对或已验证用途，避免模型混淆不同图中的人物与动作。
5. 命中或不确定时补查前后邻帧与动作中段，排除卡牌精灵、其他角色、普通战斗和仅穿着战斗服的亮相。对没有命中的集数、被窄颜色条件淘汰的样本和不同服装进行较宽条件的负例补查。
6. 通过候选在局部窗口每秒约5帧精查，再按实际解码帧精修边界。主代理查看必要的连续帧、短片和剪口前后画面，确认本地模型判断。只看一张命中截图不足以确认整段动作或出点。
7. 将确认结果导出到独立素材文件夹，执行下述检查，交付集数范围、文件数及剩余不确定项。默认不制作审阅网页，用户要求时再做。

## 变身演出的关键边界

寻找角色完整的仪式性动作与视觉演出。黑背景本身不能证明变身，普通魔法阵或挥杖也可能是假阳性。

命中后，动作结束之后连续出现的黑底魔法阵、抽象光带、枝状光效、旋流与闪光属于该演出的尾部。保留到切回通常剧情画面之前。叠化以通常剧情场景首次显现为边界。普通剧情中的战斗和反应镜头不并入。完整演出的导出范围与后续混剪只选某个动作阶段分别记录。

起点也要向前检查，避免从发光动作中间切入。采用帧对齐的入点和排他出点，检查最后保留帧及第一张排除帧，黑帧不能自动等同于结束。

## 时间码、缓存与交付

- 原片秒数以源 PTS 为准。局部规范化解码时记录窗口原点、局部帧率、入帧、排他出帧及对应源时间，避免局部时间冒充原片时间。精确导出可重编码，不以快速 stream copy 保证帧级剪口。
- 缓存键包含源文件标识、采样/裁边规则、模型和提示版本、排除配置。支持续跑，仅复用成功且仍适用的结果。接口失败、非法响应与明确负例分开记录。
- 原始回答、特征缓存、候选、最终清单和人工修正放在项目 work 下。云端只读摘要和必要的少量图像，不批量上传全片或逐条回传本地问答。
- 默认保留原声和有效画幅，不增加配乐、字幕或增强处理。文件夹只放独立视频，日志另存。
- 文件名按“第10集 · 橙红便服 · 18：02.00–18：24.12.mp4”，Windows 时间分隔使用全角冒号。同集多段补充短标识防止重名。文件名不附加尾部特效说明。
- 清单保存源文件、角色/服装、源入出点、裁边与帧率、判定证据、人工覆盖、输出路径。每段检查全程解码、时长、实际帧数、音轨、首末帧和源片对应。
- 交付时说明使用的检索策略与覆盖范围。没有全量人工真值时，不宣称零漏检。
