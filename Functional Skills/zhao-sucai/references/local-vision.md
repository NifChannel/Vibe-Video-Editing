# 本地视觉检索

## 接口与故障处理

由 Codex 按[视觉依赖](../../../安装与外部依赖.md#vision)自动准备并定位 LM Studio 或兼容回环接口，写入 vision_url / vision_model。先请求配置地址下的 `GET /models`，以实际模型 ID 为准，检查目标确为具备视觉能力的 Qwen3-VL-8B Q4 及对应视觉组件。模型名称以实际服务响应为准。

通过 `POST /v1/chat/completions` 发送单张本地图片的 base64 data URL 和简短文字问题。图片只发给本机服务。用当前服务已验证支持的结构化输出约束字段，仍需校验 JSON、必填布尔字段和响应是否完整。原始响应本地留档，失败有限重试并记录原因，避免无限重试。

服务未启动时，可检查已安装的 `lms` CLI，并依据本机 `lms --help` 和模型清单启动回环服务、加载模型。并发从1开始，根据显存和稳定性调整，避免对单卡启动大量推理。用一张已知正例和一张负例验证确实收到图像。

若用户要求“接口不可用就停止”，在接口诊断、允许的启动及小样验证失败后停止检索，报告连接、加载或视觉能力的实际错误。不能悄悄改用 GUI、云端模型或其他模型。一般任务也先说明接口故障，再由已授权路径处理。

## 提问方式

单图询问可见事实，如“目标人物是否可见”“背景是否近空黑”“是否有人物周围的曲线发光轨迹”“是否处于抬臂、旋转等仪式动作”“是否可能是卡牌精灵或普通战斗”。设定 unsure 或 unknown，避免强迫模型二选一。角色和光效条件按当前项目正例制定，不能把粉色当成普适要求。

模型不负责生成时间戳。请求对应的源 PTS、候选 ID 和图片路径由程序绑定。事实匹配后再看邻帧，必要时用有序短序列问动作连续性，但必须验证多图推理可靠性。

正反例应覆盖容易混淆的普通亮相、战斗和不同光效变体，不把某个角色的服装或舞台条件当作通用规则。

## OP、ED 与预告

在低分辨率帧上比较重复序列的多处画面锚点、顺序及偏移，排除已证实的公共段。不能因单帧相似或时长相同就判定固定片头片尾。换 OP、特殊集、最终集、转码和删减版分组核验。

片尾可能仍有正片。固定跳过首尾的授权只对当前片源和当前任务有效，不继承其他项目的集数或秒数规则。

## 尽量少用云端 token

本地运行抽帧、像素筛选、Qwen事实判别、邻帧复核、负例补查和日志汇总。主代理只读取候选数量、失败数量、未命中集数及必要图像。需要降低成本时先缩减云端审阅与日志体量，不能仅因本地推理 token 多就过度稀疏采样。
