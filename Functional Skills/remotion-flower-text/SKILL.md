# remotion-花体字skill

这是 vibe-video-editing 的字幕专项流程，也可独立调用。显示名称为「remotion-花体字skill」，技能标识为 `remotion-flower-text`。由当前主代理读取和执行，无需创建子代理。

## 何时调用与优先级

- 用户明确说需要花字、花体字、动态重点字幕，或指定花字模板时启用。
- 未明确说花字，但参考视频中明显存在关键词动效、强调牌、字形/版式变化时，也应主动启用。先看实际视频，不能仅因视频属于广告就判定需要花字。
- 没有花字需求或证据时，保持主 video-editing 的普通字幕一致性规则。
- 本次明确要求和已认可版本优先于本流程默认值、模板与上游技能。只修改要求调整的文字层，不连带重剪画面、重做声音或改变已认可的普通字幕。

## 先分析，再选模板

1. 阅读定稿、标色/出镜要求、实际录音及既有字幕时码。稿件内容锁定；花字不改词、数字、单位、否定词、观点和顺序。不得为了模板槽位删改文案。
2. 查看示例的代表片段和连续帧，记录节奏、情绪、普通字幕与重点字的关系、字号、位置、字色、描边/阴影及入退场。区分观察与暂定设计。
3. 按视频风格选择主字体方向和配色，再阅览模板库。快节奏、强关键词的广告可优先考虑非衬线粗体；叙事、传统、雅致等风格可考虑衬线或书写感字体。它们是判断依据，不是按题材机械套用的规定。检查当前底片对比度和人物遮挡，不默认所有视频都用黄黑字或非衬线字。
4. 本版不附带花字模板。用户可自行上网寻找可用模板库并提供链接；Codex 按需下载、核对许可、安装和适配。没有模板时在当前 Remotion 项目实现新效果，先核对真实画面与源码，不只凭名称选择。安装见[字幕依赖](../../安装与外部依赖.md#captions)。
5. 先做包含真实底片、真实文案和声音的代表片段，检查后应用到全片。不要为了展示模板库，把每种效果都塞进一条片中。

从旧版制作修订版或对比版时，按每版的叙事目标和用户要求，逐处复核继承的花字标记。仍适合强调的沿用，已失去强调理由的台词恢复为本版普通字幕。分别更新各版的字幕清单和渲染输入。

需要定位库、改编现有组件或新增入库时，读 [模板库使用与保存](references/library.md)。

## 按自然语句组织字体

仅在本技能启用的视频/段落中应用：

- 没有明确要求时，每 **1–2 句自然语句共用一种基础字体**，以 `。` 为主要分句标准。行文不严格或缺少句号时，按完整意思和口播停顿做语义分割；`？`、`！` 等可辅助判断。
- 逗号、字幕换页、半句话或每个关键词不自动触发换字体。长句可以分屏显示多条字幕，仍继承同一基础字体。
- “一种基础字体”指同一字体家族与相容的字形。重点可以调整字号、字重、颜色、底牌、描边和动效；默认覆盖模板原字体，使它继承本自然语句的基础字体。用户明确要求其他字体时按其要求执行。
- 不要求每个分句都换成全新字体；相邻 1–2 句可共用。也不强制固定字体轮换顺序。跨整片保持同一视觉体系，在合理的自然语句边界变化。
- 同时保护语义词组与数字单位，例如「不到6000块」是完整重点，不能丢掉「不到」、把单位漏在牌外或拆出歧义。

## 自然排布：保留普通信息，标出重点

- 先判断一句中的关键信息，再安排模板。价格、工期、结果、关键承诺和行动词可成为重点，不能因为模板能动就把每个词都做成花字。
- 普通信息沿用本片基础字幕方案；**正常显示不等于强制简化已认可的效果**。已认可的普通字幕字体、入场和排布应保留，仅按本次要求给重点叠加合适的模板处理。
- 模板可只作用于句中的一个词组。例如同一句都用微软雅黑，普通叙述保持原样，只给「不到6000块」加价格牌；另一句都用标题黑，仅给「两天」增加强调。
- **禁用影响阅读的删除线**：不要使用 `line-through`、划掉价格、横线穿字或其他穿过字身的划除效果，即使文意是“不要花这么多钱”也不用。改用完整可读的字色、底牌、字下强调或分开的对照排布；模板自带此类线条时先移除，再核对入场及完整显示阶段。
- 重点牌应承载或修饰原有那一份文字，不另叠一套同文字幕。尽量随原字幕就近排布，不无故把词拆散到画面各角。
- 无需每句都有夸张模板。重点的出现频率、幅度、颜色和停留时间服从叙事与实际语速。所有重点花字模板均遵循下述片内一次与批量频率规则；用户提供的重点效果也包含在内。
- 并列信息需要比较或汇总时，随口播进入后共同保留至讲完；不要独立倒计时提前消失。

## 花字数量、模板去重与低频 emoji

- 需要花字的视频，每片至少安排 **3次**重要信息的花字强调，优先做到 **4–5次**，按语义和读字时间选择真实重点。普通换页、基础入场、只换黄色文字不充当额外重点模板来凑数；模板不足时在项目中设计新效果，在当前 Remotion 项目实现，不擅自入公共库。
- 同一花字模板在同一视频中只出现 **1次**。同一完整语义组连续出现、共同保留的多个元素算一次；退出后在另一处再次使用算复用。仅改文案、字体、配色、位置或大小仍是同一模板；不能换个ID规避。普通基础字幕可沿用一致字体与入场，重点模板单独计数，不要求每页普通字幕换花样。
- 批量任务中，同一模板在每 **5个视频里最多用于3个视频**；持续批次按最近5个视频复核。建立项目级使用记录，写明视频、重点时间段、模板身份、版本及emoji。一个视频的多个修订只计最终选中版本一次；不足5条时不虚构剩余成片，保留当前计数用于后续安排，不临时给同模板换名。
- 可以少量使用与语义对应的 emoji，例如点赞、房子、小红心；不强制每片添加。批量任务目标约 **每5个视频有3个使用emoji**，每个使用emoji的视频 **全片只出现1次、一个emoji符号**。同一emoji跨多处再次出现或一组多个符号都不符合“一次”。短批次适度安排并记录，后续补齐整体比例，不能在一片中加多个凑配额。
- emoji辅助信息，不能替代原稿文字、改变含义或掩盖关键词，也不单独计为最低3次花字中的一次。显式加载能正确显示的字体或本地素材，检查实际渲染无方框、无缺字、无遮挡。

## 设计新花字

没有模板或用户要求原创时，在当前项目使用真实可用的 Remotion API 构建文字组件，按需读 [Remotion 接入与验证](references/remotion.md)。不依赖固定组件库，不编造组件名称。

依据当前字体、底片和语义安排位置、缩放和入退场。围绕实际基线与测量框处理缩放，避免文字抖动；多行保留清晰间距。已认可的普通字幕不因制作花字而整体重做。按帧驱动时序，保存参数与实际渲染入口，不只写规划。

## 实现、检查与交付

- 分开管理原片、声音和文字层。使用词级时间/校对时码与整数帧安排花字，不按平均字数分配整段口播时码。不因本技能重新生成配音。
- 用户要求给花字加音效时，加载 [花字音效](../flower-text-sfx/SKILL.md)。传递确认的重点词组、动效类型、成片帧率、入场帧和实际动作落点，音效按该模块选声和对齐。
- 模板必须在源码或渲染调用中真正使用。记录模板来源、版本/commit、具体组件、字体覆盖和项目派生修改；保存其许可证。字体/音乐授权单独核对，模板的 MIT 不等于任意字体可商用。
- 先等待实际字体加载，再测量文字。按最大缩放/过冲、平移、字重、描边、阴影和底牌尺寸检查整个运动区间。文字与文字不重叠，底牌不遮住相邻字；避开人物关键部位、画面信息和平台安全区。不能把白字盖在大黄字上来突出重点。
- 按语义重排、合理分行或调整入场与间距；不靠删字、极小字号或强压单行解决溢出。必要时按实际底片改编模板，不能把横屏组件机械缩小成手机上读不清的字。
- 抽查普通信息、重点入场、最大过冲、长句、牌与正文交界、字体变化和结尾；核对文字顺序、否定词和数字单位。静态终帧不能证明整个动效无重叠。
- 修订版和对比版在最终导出前，按各自的字幕清单逐处核对原花字位置的实际渲染样式，包括已恢复为普通字幕的台词。
- 返回主 video-editing 流程完成全片解码、帧数、音画时长、字幕范围和响度检查。仅改文字时核实原画面和声音没有非预期改变；不能把机器检查写成人工听审。
- 交付成片及实际需要的可编辑组件、字幕 JSON/SRT、来源/修改记录和检查报告。新设计默认只留当前项目；只有用户明确要求保存，才登记到模板/字体库，不自动安装系统字体或更新全局风格。
