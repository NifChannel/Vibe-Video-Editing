# 原声口播默认：Qwen 基模与 F 流程

适用于原录口播、解说和采访。此处约定识别与质量流程；具体节奏、响度、剪点和视觉规范由当前项目决定，用户明确要求优先。

识别前先按[口播节奏选择](speech-rhythm.md)读取本项目 `speech.style` 并解析到实际规划。缺少项目配置时采用默认口播风格，明确无口播则跳过整理。用户选择舒缓或紧凑时只改变声音节奏依据，不降低以下质量要求。

## 工具与模型职责

- **基模：Qwen3-ASR-1.7B；词/字时间：Qwen3-ForcedAligner-0.6B。** 对齐的是实际识别并校对的录音内容，不把客户定稿强制对齐成录音里没说过的话。Qwen 不一定逐字保留犹豫和误起，文字流畅不代表声音已无口误。
- **Codex 做语义决定，声学证据校准剪口，Blazerior 的词表/停顿/EDL 和 FFmpeg 执行。** 仅保留实际需要的第三方工具，来源见 vendor/blazerior-videoediting/README.md。识别和对齐使用 scripts/qwen_transcribe.py；`dump_words.py`、`pauses.py` 仍实际运行。音频专用适配器不是上游原生 build.py，记录实际执行路径。
- 先读[本机运行环境](local-runtime.md)。按自动配置选择并核验本机实际 GPU；模型参数、前向张量和显存记录都要支持 GPU 执行。不可静默回退 CPU、Whisper-small 或云端服务。文件读取、分词、声学测量和 FFmpeg 的 CPU 运算不属于模型 CPU 回退。

## 1. 原片与时间基准

新制作或从零比较时从原始素材新提取完整、未强降噪/门限/删静音的人声分析音频；不能拿旧成品、旧转写或旧 EDL 冒充从零处理。普通修订可复用哈希、模型配置、音轨和时间域一致的可靠中间产物，记录复用依据。

记录源文件/音轨、哈希、采样率、帧率、时间起点和分析偏移。源片字词时码、剪后输出时码与局部样本偏移分开管理。先处理全片，再按同一原片内容映射截取对比样本，不能只修几个样本就交付“全片已完成”。

## 2. Qwen 识别、对齐与原始证据

默认离线本地模型、FP16、batch=1；按本机已验证配置加载，不安装 NVIDIA 依赖覆盖 AMD PyTorch。显存不足先查实际占用及批量/分块，设备不可用时报告，不私自换基模。

用同一原片时间轴选安静分块边界，保留上下文重叠。已验证起点是约 20—26 秒核心、两侧各 1.5 秒上下文；可按素材调整。重叠须以字词与时间共同核对并留消重记录，不能把分块接缝造成的重复当成说话者重录。无法可靠拼接、空识别、异常重叠/长词或截断进入复核。

```text
python scripts/runtime_config.py run-qwen --input "<原片绝对路径>" --output-dir "<本项目>/work/speech/asr"
```

参数说明以 `--help` 为准。`--start/--duration` 仅作局部复核或当前授权样本，返回时码包含原片偏移；成片回查时将成片作为新的输入时间域并保存独立输出目录。输出目录已存在时拒绝覆盖。

保存每块原始识别与原始对齐、`transcript.raw.json`、校对副本和独立纠正记录。适配器的 `transcript.json` 为 Blazerior 兼容初稿，**不是已校对结论**。没有可用词概率时，原始置信度为 null，兼容字段 `p=-1` 明确表示未知，不能伪造高置信度。

复制 vendor 工具到本项目，使用同一 Python 实际执行：

```powershell
& $speechPython "<项目>/tools/dump_words.py" "<项目>/work/speech/asr/transcript.json"
& $speechPython "<项目>/tools/pauses.py" "<项目>/work/speech/asr/transcript.json" 0.24
```

此处 0.24 是列出候选的门限，不是统一保留的停顿长度。

## 3. 全片语义审查与定向复核

先判断有效内容与废弃表达，再判时间和声音。逐段读完整句子及原稿上下文；相邻重复半句、词首误起、重读、异常词长、空白中的周期性字音、识别/对齐不一致、明显稿件偏离和分块接缝都要覆盖。不要只检查已知缺陷或重复字符串的次数。

- 废弃半句后有完整流畅重录：保留完整一次；相邻重复完整句择合适的一次。标题—定义、解释性重复、教学强调和列举不机械去重。
- 转写把口误“修顺”或时码把字挂到早先停顿上时，检查原录声音和实际字头/字尾，不凭文本宣布修复。
- 用**当前基模**局部重识别并重对齐，保留前后完整上下文；空结果或不一致时可把边界移到句前安静区、增加上下文或隔离末次完整表达。保留重试和失败记录。至多两次针对性调整仍不一致时列为待复核，不无限重跑直至得到想要的答案。
- ASR 错字不等于录音口误；两个模型或两次同模型输出一致也不等于已听辨。无法安全修复的实质性单字口误、缺录等不擅自拼字、TTS或改字幕掩盖，保留原声及复核片段，明确交付。

每项记录稳定 ID、原片范围、关联词/段 ID、上下文、依据、`keep/delete/shorten/attenuate/review`、理由及实际执行状态。允许录音存在原稿未完成内容，但不能把未录文字补进转写或声称稿件已完整实现。

## 4. 全片声学补查：时间与呼吸分开决定

对同一新提取原录运行 `scripts/speech_evidence.py --audio .../source16k.wav --transcript .../transcript.raw.json --output-dir .../evidence`。它保存 RMS、周期性、频谱平坦度/高频比例、词间空档、漏覆盖有声和独立的全片疑似呼吸候选，**不直接生成剪点或增益**。默认测量阈值只是已验证起点，需按录音噪底、声线和目标响度校准。

覆盖整个原录，不仅 ASR 词间空档：错误字时码可能覆盖呼吸；低能量/非周期也可能是有效送气、擦音或轻尾音。需要结合字词上下文、波形/频谱及可用的试听能力，不能把 VAD 非语音、低 RMS 或单一频谱特征等同于可删。

每个候选分别填写：**时长保留还是收紧**、**声音保留/移除/衰减还是保护字音**。保留句间停顿也必须检查声音；拖长停顿夹强呼吸时同时处理多余时间和呼吸，不能只剪两侧安静区，留下更突出的吸气。

按当前风格保留自然分句、理解和有表达作用的停顿。只在实际安全区收紧句内多余等待，不逐词硬切或统一压成某个秒数。检测到有声却未被词表覆盖的区间先复核，尤其保护汉语字头、字尾、数字与单位。

突出词外呼吸采用经确认的局部平滑增益，或连同确实多余时间删除。增益过渡要在呼吸前完成、呼吸后退出；否则中心已衰减，边缘仍会漏出强声。重叠增益窗合并，避免重复降音；复查最终响度下的残留 RMS/峰值与实际听感，不以“已减若干dB”代替验收。不用全片强噪声门。

## 5. 一份计划执行，统一映射

以本项目 `edit-plan.json` 为唯一决定来源，派生兼容 `edl.json`、音量操作和 `source-map.json`。源入出点、输出入出点、帧/采样时间基及淡化重叠明确记录。视频同步裁切在安全区选整数帧，音频换算到采样；短淡化仅用于安全连接，实际交叉重叠必须计入总长。

定剪口时和导出后都执行[词尾波形检查](speech-editing.md#词尾波形检查)，在现有剪辑与检查记录中保留两次核对结果。

从原始保留区间重组声音，连续轻度处理后按项目响度统一混音；不对每个碎片或对比样本分别归一化，不全段加速。停顿、目标响度、呼吸衰减和噪声阈值均按当前录音校准，不套用其他项目的固定数值。

保持字幕、出镜口型、B-roll、课件事件、配乐闪避与声音同一映射。上游 build.py 仅在确实适合视频重切时使用；独立音轨可用项目内样本级/FFmpeg适配器执行同一 EDL，保存实际参数，不能冒称调用未执行的上游工具。

## 6. 成品回查、耗时和交付

- 完整解码、预期帧/采样数、首尾字音、时长、响度/峰值、映射单调且不重复、剪口边缘和呼吸衰减过渡都检查。自动间隙剪切不得覆盖受保护有声核心。
- 用当前 Qwen 基模实际回查导出成品中的主要语义剪口、重要句子和重点样本；配合原片保留/删除范围及声学校验，不单凭输出 ASR 没写重复就算无重复。局部回查截在半个字上导致的错识别不直接当成成片缺字。
- 比较样本从**最终完整成品**按源映射截出，并验证样点一致；记录对照旧版身份/哈希，不回写旧成品。
- `perf_counter` 记录提取、载入、全片识别、单独对齐、局部复核、导出回查、渲染和技术检查，保留失败/重试及跳过阶段；自动耗时合计与包含语义审查/适配/排队的墙钟跨度分开。已安装模型、缓存/批量、设备、数据时长和测试次数注明，不把单次试验当成硬件通用基准。
- 有未解决项时在交付消息明确指出文件、成片/原片位置、疑点、已做检查和保留方式，并附复核片段。已无实际待复核项时无需给用户泛泛的“待复核”警示。无直接听辨能力时不声称已人工听审。
